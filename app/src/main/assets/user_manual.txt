1. INTRODUCTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Logbook & Flight Tools app is a logbook for pilots who want to:

  * Record flight legs with all relevant details.
  * Automatically compute block, flight, night and day times.
  * Automatically set takeoff and landing counts when pilot flying.
  * Compute sunrise and sunset along a flight route.
  * Manage a local airport database (IATA/ICAO).
  * Customise how each leg card looks in the Leg List.
  * Record prior flight experience (Opening Balance).
  * Back up, restore, export and import data.

All logbook data is local. See section 14.5 for the two outbound
network operations and what they send.

2. GETTING STARTED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

After installing, you see the Home screen. The top of the screen shows
a summary of your block times (section 3). Below it are the main
buttons.

Home buttons:
  * View Logbook - opens the Leg List.
  * Add New Leg - opens a blank Leg Editor.
  * Tools - opens the Tools screen (section 3.2).
  * Settings - opens the Settings screen (section 3.3).
  * User Manual - this document.

The first time you open an airport-related screen or use the Leg
Editor, the built-in airport database is copied automatically. You do
not need to do anything.

To add your first leg, tap "Add New Leg".

If you have flown before using this app, record your prior experience
in the Opening Balance screen (Tools -> Opening Balance, section 13).
It contributes to totals in the Leg List, Statistics and the PDF
logbook, and is never shown as a flight.

Several features save files: JSON backups, CSV exports, PDF exports,
and settings backups. All go to a single folder on your device called
the Work Folder. You choose it once; the app remembers it. See
section 16.

3. HOME SCREEN & NAVIGATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3.1 Block times summary
───────────────────────

The card at the top of the Home screen shows six lines of block time
totals:

  * Owner - the owner name set in Settings -> PDF/csv export format
    -> Format PDF. Hidden when no name is set.
  * Last 7 days
  * Last 28 days
  * Actual month
  * Actual year
  * Total - block time across every leg, plus the Opening Balance.

All ranges use UTC. A leg with no Off-Block time is not counted in the
first four ranges, but is counted in Total.

The summary is refreshed every time you return to Home.

3.2 Tools screen
────────────────

Tools hosts the secondary features:

  * Export PDF (ICAO/EASA Logbook) - see section 9.
  * Sun Events - the Flight Sun Calculator (section 6).
  * Airports DB - the airport database (section 7).
  * Backup Logbook - the Backup screen, which holds JSON backup,
    JSON restore, CSV export, CSV import, and Delete All (sections 8
    and 10).
  * Opening Balance (anterior flights) - prior experience (section
    13).

The bottom of Tools shows the current Work Folder. Change it via
Settings -> Work Folder.

3.3 Settings screen
───────────────────

Settings hosts:

  * Preferences - Default Fields, Custom Lists, Statistics
    Visibility, Sun Calculator Altitude, Leg Items (section 11).
  * PDF/csv export format - Format PDF and Format CSV (sections 10
    and 9).
  * Work Folder - the folder that receives every file the app
    writes (section 16).
  * Backup / Restore Settings - save and restore preferences
    (section 17).
  * App. Update - the Updates screen (section 12).

3.4 Work folder check on launch
───────────────────────────────

Each time you open Home, the app performs two checks in order:

  1. If the automatic update check (section 12) finds a new version,
     the "Update Available" prompt appears. Nothing else happens on
     this launch.
  2. Otherwise, if the Work Folder is not set or is no longer
     accessible, the app opens the folder picker so you can choose
     one. This is the same explanation dialog you would see if you
     triggered a backup or an export without a folder set.

If you cancel the picker, nothing happens. The next time you open
Home, the check runs again. A folder that was merely unmounted for a
moment (for example, an SD card with a loose contact that is pushed
back in) is not forgotten: the app keeps its record of the folder and
uses it again as soon as the card is accessible.

3.5 Back navigation
───────────────────

Every other screen has a Home button in the top-right of the top bar,
which returns to Home. The Up arrow on the left returns to the
previous screen.

4. LOGBOOK LEGS - ADDING & EDITING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

4.1 Opening the editor
──────────────────────

  * New leg: Home -> Add New Leg.
  * Existing leg: tap a leg in the Leg List.

4.2 Fields
──────────

  * Date - flight date (UTC). Tap to change.
  * Flight Number - e.g. "LH123".
  * Position - your role. Suggested: PIC, SIC, AugCrew, Dual,
    Instructor. Empty + focus shows the full list; one character
    filters it; two or more characters switch to database
    suggestions from your previous legs. Free text allowed.
  * Category - suggested: Multi Pilot, Single Pilot SE, Single Pilot
    ME, Helicopter, Glider. Same suggestion behaviour as Position.
  * PIC Name / SIC Name / Cabin Crew / Jumpseat 1 / Jumpseat 2.
  * Registration - leaving the field fills Type from the most recent
    leg with that registration. Type editable afterwards.
  * Type - leaving the field fills Category from the most recent leg
    with that type. Category editable afterwards.
  * Departure / Destination - IATA or ICAO. Autocomplete from the
    airport database.
  * Off-Block / Takeoff / Landing / On-Block (UTC).
  * Sunrise / Sunset (UTC). Fill manually, or use the Night button
    (section 4.5).
  * Block Total / Block Night / Block Day.
  * Flight Total / Flight Night / Flight Day.
  * Simulator Time.
  * IFR Total / IFR Night / IFR Day.
  * Instrument Approaches.
  * Takeoff counts: Day, Night, Total.
  * Landing counts: Day, Night, Total.
  * Simulator, Pilot Flying, IFR checkboxes.
  * Comment. If Jumpseat 1 is filled, the PDF prints it as a second
    line "J/S: ...".

4.3 Auto-calculations
─────────────────────

  * Block Total from Off-Block and On-Block.
  * Flight Total from Takeoff and Landing.
  * Block Night and Flight Night use the most accurate method
    available. If the Night button was used, a sweep over all actual
    sun events along the route is applied. Otherwise, the static
    day-by-day calculation is used.
  * Block Day = Total - Night. Same for Flight Day and IFR Day.
  * Checking Pilot Flying sets the takeoff and landing totals to 1
    and classifies each as day or night by the takeoff and landing
    times.
  * Checking IFR copies Flight values into the IFR fields. Editing
    Flight Total or Flight Night re-copies them.
  * Instrument Approaches becomes 1 when IFR Total > 0 and Pilot
    Flying is checked, but only if the field is empty. It is cleared
    when either condition is no longer met.
  * Checking Simulator computes Simulator Time from Off-Block and
    On-Block, clears the Block, Flight and IFR fields, and clears
    Instrument Approaches. If a default Simu IFR Approach is set in
    Preferences, that value is written instead.

4.4 Input formats
─────────────────

  * Time: "HH:MM" or "HHMM". Normalised to "HH:MM".
  * Duration: "H:MM" or "HHMM". Formatted as "H:MM".
  * Invalid values turn yellow. Correct before saving.
  * Enter on the keyboard clears the field's focus, triggering any
    lookup or normalisation.

4.5 The Night button
────────────────────

The Night button next to Sunrise and Sunset opens the Flight Sun
Calculator pre-filled with the current leg's airports, times and
Off-Block / On-Block. After computing, tap Apply to Leg. The editor
uses the returned data to recalculate Block Night, Flight Night and
the takeoff/landing day-night counts. See section 6.

4.6 Save / View / Edit / Delete
───────────────────────────────

  * Save stores the leg. Invalid fields block save.
  * Opening an existing leg shows it in view mode. Tap Edit to change.
  * Cancel in edit mode reverts to view mode (or discards a new leg).
  * Delete (existing leg, edit mode) shows a confirmation dialog.

4.7 Default values for new legs
───────────────────────────────

Configured in Preferences -> Default Fields (section 11.1). Only new
legs are affected.

5. LEG LIST - VIEWING, FILTERING & STATISTICS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

5.1 Summary information
───────────────────────

At the top of the list:

  * Total Block Time
  * Total Block Night Time
  * Total Simulator Time
  * Number of legs

When the filter is All, the Opening Balance is added to the three time
totals. The leg count is never affected by the Opening Balance.

When the filter is anything other than All, the Opening Balance is
not included.

5.2 Filtering
─────────────

Filters:
  * All
  * Last 7 days
  * Last 28 days
  * Actual Month
  * Previous Month
  * Actual Year
  * Custom (start and end date)

Tap the filter button next to the search icon.

5.3 Searching
─────────────

Tap the search button to open the advanced search. Build a list of
conditions and combine them with AND or OR.

Building a condition:

  1. Tap an operator: equals or contains, is not or does not contain,
     is on or before, is on or after.
  2. Pick a field.
  3. Enter a value.

Value entry by field type:

  * Text: type the value. Suggestions from your logbook appear after
    two characters.
  * Boolean: choose true or false from a dropdown.
  * Time: a date field and a time field. Fill only the date, only
    the time, or both.
  * Duration: "H:MM" or "HHMM".

Tap OK to add the condition. Each row has a delete button.

The switch at the bottom selects AND or OR.

Tap Search to open the results. The results screen has a "Search
Results" title. Tap Back to return to the search screen.

A not-equals condition includes legs whose field is empty. To exclude
empty fields, add a second condition for the same field with
not-equals and an empty value, combined with AND.

Search never includes the Opening Balance.

5.4 Statistics
──────────────

Tap the statistics button. Two modes:

  * By Type - one row per statistic, one column per Position, plus a
    Total column. Which rows appear depends on Preferences ->
    Statistics Visibility.
    The Opening Balance always contributes to By Type, regardless of
    the Leg List filter. Rows with a position contribute to the
    matching column; rows without a position appear under a Prior
    column.

  * By Month/Year - one row per year with Block Total, Block Night,
    number of legs, and Simulator time. Tap a year to expand into
    months.
    The Opening Balance adds a single Prior row that does not expand.
    Its position depends on the earliest start date you entered. If
    no start date was entered, it appears at the bottom.

The Legs count excludes simulator sessions. Simulator time appears in
its own column.

The Month/Year view always shows your whole logbook and always
includes the Opening Balance.

5.5 Customising leg cards
─────────────────────────

Preferences -> Leg Items (section 11.5) determines what appears on
each of the four lines of a leg card.

5.6 Export from the Leg List
────────────────────────────

The export icon in the filter row offers two actions:

  * Export CSV - produces a CSV of the legs currently shown (filtered
    list, or search result). The format is the one saved in
    Settings -> PDF/csv export format -> Format CSV (section 10.1).
    Filename: logbook_export_*.csv when the filter is All,
    logbook_filtered_*.csv otherwise.

  * Export PDF - when the filter is All, behaves exactly like Export
    PDF from Tools (section 9.1). Otherwise, produces a "filtered"
    PDF that contains only the current legs (section 10.2).
    Filename: logbook_filtered_*.pdf.

If the current filter or search produces no legs, the export is
blocked with a short message.

6. FLIGHT SUN CALCULATOR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Computes sunrise, sunset, astronomical dawn and dusk along a flight
route, accounting for the aircraft's changing position and cruise
altitude.

6.1 Opening
───────────

  * From the Leg Editor's Night button (pre-filled).
  * From Tools -> Sun Events.

6.2 Inputs
──────────

  * Departure / Destination - autocomplete from the airport database.
  * T/O Date, T/O Time (UTC).
  * Ldg Date, Ldg Time (UTC). The app ensures landing is after
    take-off.
  * Altitude - cruising altitude in feet. Affects the horizon used
    for sunrise and sunset.
  * Off-Block / On-Block (display only, when opened from the Leg
    Editor).
  * Waypoints - optional intermediate points.

6.3 Waypoints
─────────────

Tap Add Waypoint(s) to add a row. Each row has latitude, longitude,
and UTC time.

  * Both coordinates and time - known point at a known time.
  * Both coordinates, no time - the time is interpolated.
  * Time only - the position is interpolated along the great-circle
    arc between the surrounding known points.
  * Only one coordinate - the missing coordinate field is marked
    yellow. Correct it or clear the other before computing.

Coordinate formats:

  * Plain decimal degrees, any magnitude: 45, 45.5, -45.5, 45.04,
    -23.65438, 7.567.
  * Degrees + decimal minutes: "45 12" or "45 12.5" or "45°12.5".
  * Degrees + minutes + seconds: "45 12 24" or "45 12 24.5" or
    "45°12'24.5"".
  * A space can stand in for the degree symbol or the minute mark,
    with one space between D and M and two spaces between D, M and S.
  * Decimal values are allowed only in the last group of a multipart form (minutes for D M, seconds for D M S), or in a plain
    decimal number.

Hemisphere letters N/S/E/W (either case) are accepted before the
first digit or after the last digit, with or without spaces:
"N45.5", "45.5s", "N 45.5", "45.5 W".

A leading "-" is treated as South/West; a leading "+" is treated as
North/East. A hemisphere letter that contradicts the sign is
rejected. A minus sign after the hemisphere letter is rejected.

Compact forms such as "45124" or "4512.4" are not accepted. Use the
spaced forms or plain decimal.

Time anchoring: every waypoint time is anchored to the take-off date.
If the time is earlier in the day than take-off, one day is added. If
the result is still before take-off or after landing, the field is
warned. A flight longer than 24 hours cannot use waypoint times.

Sorting: once every non-empty row has a time you entered, rows
rearrange by time automatically and empty rows are removed.

Remove a row with the X button on the right.

6.4 Temporary (auto-filled) values
──────────────────────────────────

When you focus out of a waypoint field and the row can be completed
by the calculator, the app fills the missing coordinate and/or time
and shows the field in a slightly different style. Values in that
style are "temporary": they are the calculator's current best guess,
not your own entry.

If you change any waypoint field (coordinate or time) and leave it,
all temporary values in the route are recalculated from the current
anchors and times. You do not need to clear the field first. Your
own typed values are always kept as-is; only temporary values are
recalculated.

To confirm a temporary value as your own, type into the field. The
field reverts to the normal style and the value is no longer
recalculated automatically.

6.5 Computing the results
─────────────────────────

Tap Compute Sunrise / Sunset. The app determines the day/night status
at take-off and landing, scans the route minute by minute, and
interpolates the exact time and position of each crossing.

Results show:

  * A segment-speed line at the top (see 6.6).
  * Events found, each with UTC time and position.
  * Day/night status at Off-Block, Takeoff, Landing and On-Block.
  * Static sunrise, sunset, astronomical dawn and dusk at the
    departure and arrival airports.

6.6 Segment speeds
──────────────────

The first line of the results shows the average speed for each
segment of the route, in knots, rounded to the nearest integer. One
speed per segment:

  * No waypoints: a single speed for the departure-to-arrival
    segment, for example "450kt".
  * One waypoint: two speeds, departure-to-waypoint and waypoint-to-
    arrival, for example "452kt - 448kt".
  * Several waypoints: one speed per segment between consecutive
    points on the route, for example "345kt - 355kt - 331kt - 326kt".

The speeds are a quick way to check that your waypoints are on the
route. If one segment's speed is far from the others, a waypoint is
probably placed or timed incorrectly.

6.7 Applying results to a leg
─────────────────────────────

When opened from the Leg Editor, Apply to Leg sends the events, the
static sunrise/sunset at both airports, and the day/night status back
to the editor. The editor recalculates Block Night and Flight Night
and the takeoff/landing counts.

6.8 Save / Load / Clear
───────────────────────

  * Save State stores the current inputs (airports, dates, times,
    altitude, waypoints).
  * Load State restores them.
  * Clear resets airports, times, waypoints and altitude (to the
    default).

7. AIRPORT DATABASE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Reached from Tools -> Airports DB.

The app uses a local airport database (IATA, ICAO, name, city,
country, coordinates, elevation, timezone). It is used for
autocomplete in the Leg Editor and the Flight Sun Calculator.

7.1 Built-in database
─────────────────────

A default airport database is included with the app. It is copied to
internal storage on first airport-related use.

7.2 Updating
────────────

  1. Open the Airports screen.
  2. Tap Update Airport DB.
  3. The latest database is downloaded.
  4. The status text shows the download date.

7.3 Managing
────────────

  * Edit Airport Database - opens the Airport Editor.
  * Export Airports - saves the merged database as
    airports_export_<millis>.json to your Downloads folder. A toast
    confirms the export.
  * Clear User Modifications - removes airports you have added,
    edited or deleted.
  * Delete Entire Database - permanently removes the airport
    database.

7.4 Airport Editor
──────────────────

  * Search - by partial IATA, ICAO, city or name.
  * Add - fill in fields and tap Save.
  * Edit - select, tap Edit, modify, tap Save. ICAO cannot be
    changed; to change it, delete and re-add.
  * Delete - select, tap Delete, confirm.

Changes are stored immediately and reflected in autocomplete.

8. BACKUP & RESTORE (JSON AND CSV)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Reached from Tools -> Backup Logbook.

8.1 Two formats, one purpose
────────────────────────────

The Backup screen saves your logbook, in one of two formats:

  * JSON backup - Backup Logbook (JSON). The full backup. Contains
    every leg and the Opening Balance. Restoring a JSON backup
    replaces the current data (see section 8.4).

  * CSV backup - Export Logbook (CSV). A human-readable backup of
    the legs you entered in this app. Contains every leg, in a
    format that can be opened and edited in any spreadsheet. It
    does not contain the Opening Balance. To back up both the legs
    and the Opening Balance, use JSON.

Both formats write their files into the Work Folder (section 16).

8.2 Creating a JSON backup
──────────────────────────

  1. Open Tools -> Backup Logbook.
  2. If no work folder is set, the intro dialog explains that a
     PilotLogbookFoss folder will be created inside the folder you
     choose. Tap Continue to open the picker. If you have set a
     folder, but it is currently unreachable, the picker re-opens.
  3. Tap Backup Logbook (JSON).
  4. The app creates a JSON file, reads it back, and compares counts.
  5. The 10 most recent JSON backups are kept. Older ones are
     deleted automatically.

A verified backup of your current data also runs automatically before
any operation that could destroy or change it:

  * Before restoring a JSON backup.
  * Before Delete All.
  * Before importing a CSV file.
  * Before downloading an app update.

If the backup cannot be verified, a warning dialog appears: "Old
database is not saved. Continue anyway?". You choose to continue or
cancel.

8.3 Creating a CSV backup
─────────────────────────

  1. Open Tools -> Backup Logbook.
  2. If no work folder is set, the picker opens (with the intro
     dialog first). After you pick, the export continues
     automatically.
  3. Tap Export Logbook (CSV).
  4. The app writes a CSV file directly to the work folder.

Contents:

  * Every leg in the database.
  * One column per leg field, in database order.
  * Timestamps in raw milliseconds (for example 1762480600000),
    which is how the database stores them.
  * Durations in raw integer minutes.
  * Booleans as "true", "false", or empty when null.

The CSV is designed to be readable and editable in a spreadsheet.
You can open it, inspect the legs, adjust fields, and save it back.

The CSV backup does not contain the Opening Balance (prior
experience). To back up both the legs and the Opening Balance, use
the JSON backup (section 8.2).

8.4 Restoring a JSON backup
───────────────────────────

Button: Restore from Backup (JSON). The screen warns: "WARNING: ALL
old DB will be lost".

  1. Tap Restore from Backup (JSON).
  2. Confirm "This will replace ALL existing data...".
  3. If no work folder is set, the picker opens (with the intro
     dialog first). After you pick, the flow resumes.
  4. A verified backup of your current data runs first. If it cannot
     be verified, a warning dialog asks whether to continue.
  5. A list of JSON backups in the work folder appears, newest
     first. Pick one.
     If none are found, "No backups found" appears with a "Browse
     elsewhere" button.
  6. "Browse elsewhere" opens a system file picker for a one-off
     external file.
  7. The app clears the legs table and inserts every leg from the
     backup. The Opening Balance is replaced only if the file
     carries an Opening Balance section (as all current backups
     do).

8.5 Importing a CSV backup
──────────────────────────

Button: Import Legs (CSV). The screen states: "Legs will be added to
existing DB".

  1. Tap Import Legs (CSV).
  2. A confirmation dialog appears: "Legs database will be altered.
     Continue?".
  3. If no work folder is set, the picker opens (with the intro
     dialog first). After you pick, the import resumes.
  4. A verified backup of your current data is created first. If it
     cannot be verified, a warning dialog asks whether to continue.
  5. A list of CSV files in the work folder appears, newest first.
     Pick one. "Browse elsewhere" opens a system file picker.
  6. The CSV Import screen opens. It shows the file name, the
     number of data rows, and one mapping dropdown per column.
  7. Files produced by this app are mapped automatically. Adjust
     any column manually if needed. Leave a column on "Ignore" to
     skip it.
  8. Tap Import. The app inserts the rows, then shows a summary:
     how many were imported, how many were skipped, how many had
     errors, and a short reason per skipped row (up to 20).

Important: CSV import adds rows to the existing logbook. It does not
delete, replace or merge. Importing the same file twice produces
duplicates. To replace the logbook entirely from a CSV backup,
first clear the logbook (Delete All, section 8.6), then import.

The CSV import does not create or modify the Opening Balance.

8.6 Delete All
──────────────

Tap Delete All Logbook Datas. A confirmation dialog appears. After
confirming, the app runs a verified backup (with the same continue-
anyway warning on failure), then clears both the legs table and the
Opening Balance.

8.7 Restore behaviour summary
─────────────────────────────

  * JSON restore replaces legs and Opening Balance.
  * JSON restore of an old backup (created before the Opening
    Balance feature existed) replaces legs only and leaves the
    Opening Balance untouched.
  * CSV import adds legs to the existing logbook. It never touches
    the Opening Balance.

9. PDF LOGBOOK EXPORT (TOOLS -> EXPORT PDF)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Landscape A4 printable logbook in the ICAO / EASA (AMC1 FCL.050)
layout. This is the standard logbook PDF. It covers the whole logbook
(or a chosen range), unlike the filtered PDF from the Leg List (see
section 10.2).

9.1 Exporting
─────────────

  1. Tap Export PDF (ICAO/EASA Logbook) on Tools.
  2. If no work folder is set, the picker opens (with the intro
     dialog first). After you pick, the range dialog appears.
  3. Choose:
       * All - every leg.
       * From - To - legs whose Off-Block date falls in the range.
       * Last N pages - the last N printed pages.
  4. Tap Generate. The PDF is written directly to the work folder.
     Filename: logbook_<date>.pdf. A toast confirms the export.

9.2 What appears on each page
─────────────────────────────

  * Header left: "Owner: <name>" (hidden when empty).
  * Header centre: "Pilot Logbook".
  * Header right: the date range of the legs on that page.
  * Table header (two rows).
  * One row per leg.
  * Three totals rows:
      1. Total this page.
      2. Total from previous page (every leg up to the previous
         printed page, plus the Opening Balance).
      3. Total time (every leg up to this page, plus the Opening
         Balance).
  * Merged Remarks cell containing the certification sentence, your
    signature if set, and your name.
  * Page number at the bottom centre.

The Opening Balance is never printed as a leg row. It only
contributes to the running totals, including on the very first
printed page.

9.3 Last N pages
────────────────

The Last N pages export contains only the most recent N printed
pages, but each page keeps its numbers, totals and page number as if
the whole logbook were printed. For example, if your logbook fills 20
pages and you export the last 3, the resulting PDF contains pages
18/20, 19/20 and 20/20.

If you enter a number larger than the current page count, the whole
logbook is printed.

9.4 Configuring the PDF layout
──────────────────────────────

From Settings -> PDF/csv export format -> Format PDF:

  * Rows per page - 13, 15, 18, 20 or 25. Default 18.
  * PDF font - Sans-serif, Serif or Monospace.
  * Alternate row background.
  * Owner name (printed in the header and at the bottom of the
    Remarks cell).
  * Signature - Set Signature to sign on the screen; Remove to
    delete.
  * Page layout - margins, title height, header row height, page
    number area.
  * Column widths.
  * Text sizes.
  * Live scale indicator.

Set Defaults restores the layout fields (margins, heights, widths,
text sizes, font) but not rows per page, owner name or signature.
Tap Save to keep your changes.

Leg Items customization affects only the on-screen Leg List; it does
not change the PDF layout.

10. EXPORT FROM THE LEG LIST (PDF AND CSV)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The export icon in the Leg List's filter row is for exporting what
you are currently looking at, in two formats: PDF and CSV. This is
not a backup (see section 8 for backups).

The exported file always contains exactly the legs currently shown:

  * In normal mode, the legs matching the active filter.
  * In search mode, the search results.

If no legs are shown, the export is blocked with a short message.

10.1 Export CSV (filtered)
──────────────────────────

Tap the export icon, then Export CSV.

The format is configurable in Settings -> PDF/csv export format ->
Format CSV:

  * Format 1 - PDF columns. 24 columns matching the printed logbook
    layout. Export-only; not importable.
  * Format 2 - raw database values. Every field as stored.
    Includes simulator legs.
  * Format 3 - formatted database values. One date column, four
    time-of-day columns, durations formatted as you choose.

Date format (7 options) and duration format (4 options) are also
configurable.

Filename:
  * logbook_export_*.csv when the filter is All (and not in search
    mode).
  * logbook_filtered_*.csv for any other filter, or a search result.

Unlike the Backup CSV (section 8.3), this export:

  * Contains only the current filtered set, not the whole logbook.
  * Uses the format you configured, not the raw database format.

10.2 Export PDF (filtered)
──────────────────────────

Tap the export icon, then Export PDF.

When the filter is All (and not in search mode), Export PDF behaves
exactly as Tools -> Export PDF (section 9.1): same range dialog, same
standard logbook PDF, filename logbook_<date>.pdf.

When the filter is anything else, or when you are on a
search-results screen, Export PDF produces a "filtered" PDF
containing only the legs currently shown:

  * Header: owner (left), "Pilot Logbook" (centre), and either the
    filter's date range or the literal "filtered Legs" (on search
    results) on the right.
  * Two-row column header, identical to the standard logbook PDF.
  * Body: rows per page plus three additional leg rows per page.
  * Last page: one row fewer than the other pages, plus a single
    "Total" row showing the durations and counts summed across
    every filtered leg.
  * No certification sentence, no signature, no owner name at the
    bottom.
  * Footer: "Page N / M" and the generation timestamp.

Filename: logbook_filtered_<date>.pdf.

10.3 When the filter is All
───────────────────────────

With the filter set to All, the Leg List's export icon behaves as
follows:

  * Export CSV produces logbook_export_*.csv, in the format you
    configured. It still contains every leg.
  * Export PDF opens the same range dialog as Tools -> Export PDF
    and produces the standard logbook PDF.

10.4 Summary of formats and purposes
────────────────────────────────────

  * Backup JSON (section 8.2) - the full backup. Legs + Opening
    Balance. Restorable.
  * Backup CSV (section 8.3) - a human-readable, editable backup of
    the legs. Restorable by import into an empty logbook.
  * PDF from Tools (section 9) - printable logbook, full or ranged.
  * Leg List CSV (section 10.1) - filtered export for any purpose.
    Not a backup.
  * Leg List PDF (section 10.2) - filtered PDF of the current legs.
    Not a backup.

12. UPDATES & VERSION MANAGEMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Reached from Settings -> App. Update.

12.1 Manual checks
──────────────────

Tap Check for App Update. The app contacts the update server and shows
one of: no update available, invalid updates information, could not
reach update server, or an update-available prompt.

Every manual check records the current date and time in the Last
Check line.

12.2 Automatic checks
─────────────────────

Two switches at the top:

  * Automatic check for updates - master switch. When OFF, no
    automatic check runs. When ON (default), automatic checks are
    allowed.
  * Check on every app start - only meaningful when the master
    switch is ON. When ON, the app checks every time you open it.
    When OFF (default), the app checks at most once every 7 days.

If the automatic check finds a new version, the "Update Available"
prompt appears on Home. If it does not, and the Work Folder is not
set or not accessible, the app then opens the folder picker (see
section 3.4).

12.3 Last Check
───────────────

"Last check: never" or "Last check: dd.MM.yyyy HH:mm" (UTC).

12.4 When an update is found
────────────────────────────

  1. The app prepares a verified backup of your logbook in the work
     folder. If no work folder is set, the picker opens (with the
     intro dialog first). The backup and download resume once you
     pick.
  2. If the backup cannot be verified, a warning dialog appears:
     "Old database is not saved. Continue anyway?". Choose Continue
     to proceed with the download anyway, or Cancel to stop.
  3. An "Update Available" dialog appears with Download / Later.
  4. Tap Download. The update is handed to your device's download
     service. You can leave the app; the download continues in the
     background with a system notification.
  5. When the download finishes, tap the completed notification to
     open the file. Your device's installer (or Files app) opens and
     offers to install.

Tapping Later does nothing else. The next auto check respects the
7-day throttle.

12.5 The download
─────────────────

Updates are always downloaded to your device's Downloads folder and
opened by the system when you tap the completed notification. You can
also find the file in your Downloads folder or Files app.

The app does not download in the background on its own. Downloads
only start when you tap Download.

13. OPENING BALANCE (PRIOR EXPERIENCE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Records flight experience accumulated before you started using this
app. Its purpose is to make the totals in the Leg List, Statistics and
the PDF reflect your full career.

The Opening Balance is never shown as a flight leg.

13.1 Reaching it
────────────────

Tools -> Opening Balance (anterior flights).

13.2 Entering your prior experience
───────────────────────────────────

Two styles, which can coexist:

  * Detailed - one row per aircraft type, position, category, or any
    grouping that makes sense to you.
  * Last-total-line - a single row holding the cumulative totals
    printed on the last page of your paper logbook. Leave type,
    position and category empty in that row.

Any number of rows is allowed. All rows are summed whenever the app
needs a single figure.

13.3 Adding a row
─────────────────

From the list, tap Add. All fields are optional.

13.4 Auto-fill
──────────────

Block, Flight and IFR groups (Total, Night, Day): entering two of the
three calculates the third. Night is the reference. When all three
already have values and you edit one, the reference is always Night.
A calculated value of zero is stored empty. Negative results are left
empty.

Takeoff and Landing groups: same rule with Day, Night, Total.

Category and pilot-function times:
  * When you enter a Block Total and a Category, the three
    single-pilot/multi-pilot fields are filled in.
  * When you enter a Block Total and a Position, the four pilot-
    function fields are filled in.
  * Recalculations replace any value you typed earlier.

13.5 Editing / deleting
───────────────────────

Tap a row to open it. Change any field and tap Save. Cancel discards.
Delete removes the row.

13.6 How the Opening Balance affects the app
────────────────────────────────────────────

  * Leg List summary card: added to the three time totals when the
    filter is All.
  * Statistics By Type: contributes to the matching position column,
    or a Prior column when the row has no position.
  * Statistics By Month/Year: a Prior row shows the balance totals.
  * PDF logbook: contributes to the running totals, never printed as
    a leg row.

13.7 Things to keep in mind
───────────────────────────

  * The Opening Balance is part of a JSON backup.
  * Restoring an old backup (created before this feature) leaves your
    current Opening Balance untouched.
  * The Opening Balance is not part of CSV export or import.
  * Delete All on the Backup screen clears the Opening Balance as
    well. If you want to keep the balance across a Delete All, make
    sure your JSON backup includes it (any current backup does) and
    restore it afterwards.

14. FILES, DATA STORAGE & PRIVACY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

14.1 Internal storage
─────────────────────

The app stores its private data in its internal storage directory:

  * logbook_database - SQLite database containing legs and Opening
    Balance.
  * airports.json - base airport database (created on first
    airport-related use).
  * airports_user.json - your airport modifications.
  * airports.cache - cache of the merged airport database.
  * pdf_signature.png - your signature image (if set).

Your Leg Items profiles and every other preference are stored in the
app's private preferences.

14.2 Work Folder
────────────────

A single folder, called the Work Folder, receives every file the
app creates for you:

  * logbook_backup_*.json - logbook backups.
  * logbook_export_*.csv - CSV exports of the full logbook.
  * logbook_filtered_*.csv - CSV exports of a filtered list or
    search result.
  * logbook_*.pdf - PDF exports (All filter).
  * logbook_filtered_*.pdf - PDF exports of a filtered list or
    search result.
  * logbook_prefs_*.json - settings backups.

The Work Folder is a subfolder named PilotLogbookFoss inside the
folder you pick. You pick the parent folder once. The app keeps the
10 most recent logbook backups and deletes older ones automatically;
the other files are not rotated.

See section 16 for details.

Airport database exports go to your device's Downloads folder, not
the Work Folder. Update APK downloads also go to Downloads.

14.3 Clearing data
──────────────────

Each function is separate:

  * Tools -> Backup Logbook -> Delete All Logbook Datas - clears the
    legs table and the Opening Balance.
  * Tools -> Airports DB -> Clear User Modifications - removes your
    airport modifications.
  * Tools -> Airports DB -> Delete Entire Database - removes the
    whole airport database.
  * Tools -> Opening Balance - delete rows one by one from the list.

Clearing the logbook does not remove your Leg Items profiles, your
update-check settings, or your preferences.

14.4 First launch
─────────────────

On first launch, the app does not copy the airport database yet, does
not create a Work Folder, and does not create any export or backup
file. The airport database is copied the first time an airport-
related screen opens. The Work Folder is created the first time you
use a feature that needs it and you pick a parent folder.

If you launch Home with no Work Folder set, the app prompts you to
pick one (section 3.4). You can cancel; the prompt reappears on the
next Home launch.

14.5 Privacy
────────────

All logbook data stays on your device. The app does not collect
personal information, does not use analytics, does not track usage,
and does not send any logbook data to any server.

The app makes two outbound network operations, both under your
control, and both of which send only a request without any personal
data:

  * Update check - the app contacts a public release information
    endpoint to determine whether a newer version exists. The
    request carries no personal data. It happens on Home at start,
    subject to your preferences (section 12.2), and on the Updates
    screen when you tap Check.

  * Airport database download - the app contacts a public server for
    a JSON file of airport data, and only when you tap Update
    Airport DB on the Airports screen (section 7.2).

No other outbound network operations exist.

15.1 Common issues
──────────────────

Logbook - input and saving
  * Invalid input fields - if a field turns yellow, the format is
    incorrect. Check section 4.4 and correct.
  * Instrument Approaches fills with 1 or clears unexpectedly - by
    design. Set to 1 when IFR Total > 0 and Pilot Flying is checked,
    and only if the field is currently empty. Cleared when either
    condition is no longer met.
  * IFR fields do not update when I edit Flight Total or Flight
    Night - IFR fields are copied from flight time only when the IFR
    checkbox is ticked.

Flight Sun Calculator
  * A coordinate I typed is rejected - check the accepted formats in
    section 6.3. Plain decimals like 45.04 or -23.65438 are
    accepted; compact forms like 45124 or 4512.4 are not.
  * A waypoint position or time changes when I edit another
    waypoint - by design. Auto-filled values (shown in a slightly
    different style) are recalculated from the current anchors
    whenever you leave any waypoint field. To keep a value, type
    into the field; it becomes your own entry and is no longer
    recalculated.
  * The segment speed line looks wrong - one segment's speed is far
    from the others. Check the waypoints around that segment. A
    mistyped coordinate or time usually shows up as a segment speed
    that is much higher or lower than the rest.

Opening Balance
  * The Prior row in Statistics Month/Year is not where I expected -
    its position depends on the earliest start date you entered. If
    you did not enter one, the Prior row appears at the bottom.
  * The Leg List summary card does not include my Opening Balance -
    the balance is only added when the filter is All.
  * My Opening Balance is missing after restoring a backup - if the
    backup was created before this feature, its absence is by
    design. Current backups include the Opening Balance.
  * My Opening Balance is gone after Delete All - by design. Delete
    All clears both the legs and the Opening Balance (section 8.6).
  * The first page's Total from previous page is not zero - by
    design. The Opening Balance appears in that row.

Airports
  * Airport not found - the airport may not be in the database.
    Update the database or add it manually.

Backup and CSV
  * Backup fails - check that the work folder is accessible. If
    the operation was a restore, delete-all, CSV import or update,
    a warning dialog lets you continue without the backup.
  * CSV import blocked - if the app cannot create and verify a
    backup of your current logbook before importing, a warning
    dialog appears. Continue to import anyway or Cancel.
  * The CSV from the Leg List export icon does not look the same as
    the one from Tools -> Backup Logbook -> Export Logbook - by
    design. Tools -> Backup Logbook always produces the raw
    database format. The Leg List export format is set in
    Settings -> PDF/csv export format -> Format CSV.
  * My CSV has separate date and time columns - Format 3 is
    selected. Switch to Format 2 (raw) for a single column per
    timestamp, or use Format 1 for the PDF-like 24-column layout.
  * Legs with isSimulator = true are missing from my Leg List CSV -
    the "Include simulator legs" checkbox is off. Turn it on, or
    select Format 2 (raw), which always includes them.
  * Importing the same file twice gives me duplicates - import is
    additive, not replacing. Use Delete All before re-importing.

PDF
  * PDF fonts look different from what I chose - if the font is
    unavailable the app falls back to Sans-serif. Reopen Format PDF
    and confirm the choice.
  * Numbers do not line up perfectly - choose Monospace in Format
    PDF.
  * Last N pages exported a different number of pages than I asked -
    N is the count of printed pages, not of flight legs. If N is
    greater than the total pages, the whole logbook is printed.
  * The first page's Total from previous page is not zero - by
    design. The Opening Balance appears in that row.
  * Export PDF from the Leg List produces a different PDF from
    Tools -> Export PDF - by design. With filter = All, the Leg
    List reuses the Tools flow. Any other filter, or a search
    result, produces the "filtered" PDF (section 10.2).
  * The filtered PDF has no certification, no signature and no
    owner name - by design; those elements belong to the standard
    logbook PDF only.
  * The filtered PDF ends with a Total row - it shows the sum of
    the duration and count columns across every filtered leg, not
    just the last page.

Search
  * My search for a specific time returns legs on every date - by
    design. A time-only timestamp condition compares the time of
    day, ignoring the date.
  * Not-equals includes legs whose field is empty. To exclude empty
    fields, add a second condition for the same field with
    not-equals and an empty value, and use AND.

Statistics
  * A statistic is missing from the By Type view - check that it is
    ticked in Preferences -> Statistics Visibility.
  * The Legs count is lower than the number of legs I entered - the
    count excludes simulator sessions by design.
  * The Month/Year view shows the whole logbook even though I
    filtered the Leg List - by design. Only By Type uses the Leg
    List filter.
  * There is a Prior row at the top or middle of the year list -
    this is your Opening Balance. Its position depends on the
    earliest start date you entered.

Leg Items
  * My Leg List still shows the old card layout after I saved a new
    profile - the Leg List picks up the active profile the next
    time it opens.
  * The Delete button on Leg Items shows "Can NOT Delete Active
    Profile" - you cannot delete the profile currently in use.
    Switch to a different profile first.
  * I cannot edit the Default profile - by design.
  * Position or Category suggestions do not include a value I added
    in Custom Lists - changes apply the next time you open the Leg
    Editor or Opening Balance editor.

Work Folder
  * I cannot pick the Downloads folder itself - by design. On
    Android 11+, the system refuses to grant a whole-folder
    permission on Downloads/ (and the root of internal storage).
    Pick Documents, or a subfolder inside Downloads that you create
    with your device's file manager.
  * The folder I picked is not shown by its parent in the display -
    the display now shows the full path, for example
    Download/MyFolder/PilotLogbookFoss. If the folder is on an SD
    card, the display starts with "Ext:" (for example
    Ext:Download/MyFolder/PilotLogbookFoss). If the folder is on a
    cloud provider, the display is just "Ext".
  * I removed my SD card for a moment and the app forgot my folder -
    it does not. The app keeps the folder path and uses it again as
    soon as the card is accessible. You are only prompted to pick a
    folder again while the folder is genuinely not reachable.
  * The folder picker opened by itself on Home - by design. If the
    Work Folder is not set or not accessible, Home prompts you to
    pick one, after the update check. Cancel is fine; the prompt
    reappears on the next Home launch.

Updates
  * The app never checks for updates automatically - open Updates
    and check that Automatic check for updates is ON.
  * The app is not checking on every start - Check on every app
    start may be OFF, or the 7-day timer has not expired.
  * Last check does not change when I open the app - by design. An
    automatic check that cannot reach the server does not update
    the timestamp.
  * The Update Available dialog reappears after rotation - by
    design. The dialog is preserved across rotation.
  * I tapped Download but nothing happened - the download service
    did not accept the request. Retry. The file is not on your
    device until the system notification shows progress.
  * I tapped Download and closed the app - the download continues
    in the background. Look at the system notification.
  * My update installed automatically - it did not. The app never
    installs silently. The system notification opens the file; you
    must confirm in the system installer.
  * A "Backup failed" dialog appeared during the update - the app
    could not verify its logbook backup before the download. Tap
    Continue to proceed anyway, or Cancel to stop.

16. WORK FOLDER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Work Folder is where the app writes every logbook-related file:
JSON backups, CSV exports, PDF exports, and settings backups. You
choose it once; the app remembers it.

16.1 What gets created
──────────────────────

You pick a parent folder. The app creates a folder named
PilotLogbookFoss inside it. Every file the app writes goes into
that PilotLogbookFoss folder, not into the folder you picked
directly.

When you trigger the folder picker for the first time, a short
dialog explains this before the system picker appears:

  "A folder named PilotLogbookFoss will be created inside the folder
   you choose. This folder is required for backups, exports and
   imports."

Tap Continue to proceed, or cancel to skip. The same dialog appears
whenever the picker opens, whether triggered from Home, from a
Backup screen, or from Settings.

16.2 Where the picker opens
───────────────────────────

  * If a Work Folder is already set, the picker opens at that
    folder's parent, so you can navigate from where you were last.
  * Otherwise, the picker opens at Documents.

The Downloads folder itself cannot be selected as a Work Folder on
Android 11+. If you want the Work Folder inside Downloads, first
create a subfolder there with your device's file manager, then pick
that subfolder.

16.3 What the display shows
───────────────────────────

Four screens show the current Work Folder at the bottom of the
screen: Backup, Tools, Settings, and Backup / Restore Settings. The
display shows the full path:

  * Primary storage - the parent path plus the PilotLogbookFoss
    subfolder. Example:
      Work folder: Download/MyFolder/PilotLogbookFoss
      Work folder: Documents/PilotLogbookFoss

  * SD card or USB storage - the path prefixed with "Ext:".
    Example:
      Work folder: Ext:Download/MyFolder/PilotLogbookFoss

  * Cloud provider (Drive, etc.) - the display is just "Ext",
    because the provider does not expose a readable path.

  * No folder set - "Not set".
  * Folder was set but is not currently reachable - "Unavailable".

If you picked a folder that is itself named PilotLogbookFoss, the
app uses it directly and does not create a second one. The display
shows the full path to it without a repeated subfolder name.

16.4 What happens if the folder becomes unavailable
───────────────────────────────────────────────────

The folder can become unavailable if it is deleted, if the permission
is revoked, if the SD card is temporarily unmounted, or if the
storage is detached.

The app does NOT forget the Work Folder on a temporary loss. When an
operation needs the folder and it is unreachable, the app warns you
and prompts you to pick it again. If the folder comes back (for
example, you push the SD card back in), the app uses it again with
no action from you. The stored path is only replaced when you
actually pick a new folder.

Files already written inside the folder are never deleted by the
app.

16.5 What goes to Downloads instead
───────────────────────────────────

Two things do not go through the Work Folder:

  * Airport database exports (Tools -> Airports DB -> Export
    Airports) - saved to your device's Downloads folder.
  * Update APK downloads - saved to your device's Downloads folder.

17. SETTINGS BACKUP / RESTORE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Settings Backup saves your preferences to a file and restores them
later, for example when you move to a new phone. It is separate from
the logbook backup (section 8).

What it saves
  Update settings, default Leg Editor fields, custom suggest lists,
  Leg Items card layout, PDF format settings, statistics visibility,
  default Sun Calculator altitude, and your signature image.

What it does not save
  Your flights (that is the logbook backup), your airport database,
  your Work Folder choice, or your Opening Balance.

Where the file goes
  The Work Folder. Filename: logbook_prefs_<date>.json.

How to use it
  1. On your old phone, open Settings -> Backup / Restore Settings
     -> Save Settings.
  2. Copy the logbook_prefs_*.json file from the Work Folder to
     your new phone's Work Folder (or any accessible location).
  3. On the new phone, open Settings -> Backup / Restore Settings
     -> Restore Settings.
  4. Confirm the dialog, pick the file, done.

Signature in the backup
  Your signature image is stored inside the JSON file. On restore it
  is written to the app's internal storage and set as your current
  signature automatically.
